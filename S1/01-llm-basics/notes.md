# Основы языковых моделей

S1-W01-P03 · 27 октября 2026. Конспект фактически разобранного в чате материала.

## Модель, параметры и токены

Языковая модель — математическая модель, обученная закономерностям языка. Генеративная модель использует параметры и доступный контекст, чтобы вычислять вероятности следующих токенов и последовательно формировать текст. LLM (Large Language Model) — большая языковая модель; строгой универсальной границы размера нет.

Параметры (веса) — числа, настраиваемые при обучении. Усвоенные закономерности отражаются в параметрах. Модель не является архивом всего интернета, из которого при каждом запросе извлекают готовые документы; отдельные фрагменты данных она может запомнить, но это не делает её надёжной базой документов.

Токены — единицы входного и выходного текста: слова, части слов, знаки. Это не способ хранения всей информации внутри модели. Детальный разбор токенизации запланирован отдельно.

## Обучение и инференс

| Процесс | Есть вычисления? | Меняются параметры? |
|---|---|---|
| Обучение (training) | Да: предсказание, оценка ошибки, корректировка | Да, на шагах обновления |
| Обычный инференс (inference) | Да: обработка входа, вычисление вероятностей, генерация | Нет |

Изменение ответа не доказывает изменения параметров. Новый контекст может дать новый ответ при тех же параметрах. Просьба проверить и исправить ответ тоже может выполняться при обычном инференсе. Вычисления не изменяются задним числом: выполняются новые вычисления с новым входом.

Условная запись: `answer = model(parameters, context)`. Обучение меняет parameters; дополнение запроса меняет context; инференс вычисляет answer.

## Учебная числовая модель

Модель `время = количество × вес`: для 10 элементов и фактических 30 мс нужен вес 3, для 20 элементов и 50 мс — 2.5. Один вес не даст точного совпадения с обоими примерами.

Добавляем смещение: `время = количество × вес + смещение`. Вес 2 и смещение 10 дают 30 и 50 мс. Это изменение устройства модели, а не только её параметров. Обучение подбирает параметры в рамках выбранного устройства; оно не обязано само добавлять смещение.

Для 30 элементов прогноз равен 70 мс. Если фактическое время 90 мс, ошибка — 20 мс в сторону занижения. Совпадение на учебных примерах не гарантирует качества на новых данных. Обобщение (generalization) — способность работать на новых примерах. Одна ошибка сама по себе не доказывает переобучения: возможны недостаток данных, слишком простая модель, шум измерений.

## Откуда берутся учебные примеры

В одном из основных способов предобучения следующий токен исходного текста становится целевым ответом. Примеры можно формировать автоматически из уже существующих текстов; человеку не нужно вручную подписывать каждое продолжение.

Это самоконтролируемое обучение (self-supervised learning). Данные дают целевые ответы, но процесс обучения и данные организуют разработчики.

Если исходный текст говорит «Столица Франции — Берлин», целевой ответ в задаче продолжения этого текста будет ошибочным фактически. Совпадение с источником не равно проверке истины. Один неверный пример при этом не определяет всё поведение обученной модели.

Предобучение (pretraining) формирует закономерности по большому объёму данных. Последующее обучение (post-training) помогает следовать инструкциям и давать полезные ответы. Оба этапа могут обновлять параметры; запрос пользователя к готовой модели — инференс.

## Модель и приложение

Интерфейс → сервер собирает контекст → модель генерирует ответ → сервер → интерфейс.

Приложение может подключать поиск, чтение файлов, выполнение кода, историю и внешнюю память. Результаты инструментов передаются модели в контексте. Инструменты не обязательны для анализа текста или кода, но помогают получить и проверить сведения.

База документов — внешнее хранилище. Только выбранная и переданная информация становится контекстом. Настройка языка может храниться в базе приложения и добавляться к каждому запросу без переобучения.

Новое сообщение не обязательно составляет весь вход модели: сервер может добавить историю и инструкции. Если новый разговор не получает старую историю или сохранённые сведения, модель не получает автоматического доступа к ним. Хранение информации в базе не равно её доступности в контексте.

## Контекст, примеры и проверка ответа

Контекст может содержать инструкции, данные и примеры. Несколько примеров желаемого ответа в запросе — few-shot prompting. Параметры при этом не меняются; примеры направляют поведение, но не гарантируют формат.

Если примеры убраны только из последнего сообщения, но передаются в истории, они доступны. Если убраны из всего входа, опереться именно на них модель не может.

Для объяснения функции сначала передаём сам код, затем нужные зависимости и данные. Весь репозиторий не всегда необходим. В примере getTotal вызывает getItemPrice: чтобы понять расчёт скидок, прежде всего нужна реализация getItemPrice. Даже return item.price не доказывает отсутствие скидки: цена могла быть рассчитана заранее.

Полезная инструкция: объяснять только подтверждённое кодом, отделять предположения, указывать недостающую информацию. Она не отменяет проверку результата.

## Почему возможны ошибки

Правдоподобное продолжение не обязательно истинно. Причины: недостаточный контекст, ошибки или устаревшие сведения в обучающих данных, неверная интерпретация корректного контекста, ошибки рассуждения и обобщения. Уверенный стиль не является доказательством правильности. Ошибка ответа не обязательно означает ошибку в программе обучения.

## Итог занятия

Первоначальные представления: модель как архив; инференс без вычислений; исправление ответа как изменение параметров; информация как хранилище токенов. Эти представления исправлялись на примерах с помощью преподавателя.

Самостоятельно верно решены числовые задачи о весе, смещении и ошибке прогноза. После объяснений верно различены обучение/контекст/инференс и внешняя память. В итоговом уточнении пользователь указал: закономерности отражены в параметрах; правильный контекст не гарантирует правильного ответа. Нужна отсроченная самостоятельная проверка на новых ситуациях.
