## Область видимости, затенение и TDZ

`let` и `const` имеют блочную область видимости. Внутри функции `var` имеет область видимости этой функции, а не глобальную. Вложенная область может обращаться к внешней; внешний код не получает доступ к локальным переменным вложенного блока или функции.

Затенение (shadowing) — внутреннее объявление с тем же именем скрывает внешнюю переменную в своей области. Это отдельная переменная, а не переназначение внешней.

```js
const score = 100;
function example() {
  console.log(score); // 100
  if (true) {
    const score = 200;
    console.log(score); // 200
  }
  console.log(score); // 100
}
```

TDZ (Temporal Dead Zone) — период от входа в область видимости до инициализации `let`/`const`. Само наличие TDZ не вызывает ошибку: `ReferenceError` возникает при попытке прочитать переменную в этот период. Локальная переменная уже существует, поэтому поиск не продолжается во внешней области.

```js
function first() {
  console.log(value); // ReferenceError: обращение в TDZ
  let value = 10;
}
function second() {
  console.log(value); // undefined
  var value = 10;
}
```

`var` заранее инициализируется значением `undefined`, присваивание выполняется на своей строке. Hoisting («поднятие») описывает поведение объявлений; строки кода буквально не перемещаются.

```js
function third() {
  if (true) {
    var value = 10;
  }
  console.log(value); // 10
}
third();
console.log(value); // ReferenceError, если внешняя value нигде не объявлена
```

Последняя ошибка вызвана отсутствием доступной переменной, а не TDZ.

## const и объект

`const` запрещает переназначать значение переменной, но не делает объект неизменяемым.

```js
const user = { name: 'Anna' };
user.name = 'Maria'; // допустимо
user.role = 'admin'; // допустимо
user = { name: 'Ivan' }; // TypeError
```

## Преобразования

```js
typeof null;       // 'object' — историческая особенность; null является примитивом
'5' + 2;           // '52'
'5' - 2;           // 3
Boolean('false');  // true: непустая строка
Number('');        // 0
Number('   ');     // 0
Number('два');     // NaN
Number('2.5');     // 2.5
```

`Number(str)` и унарный `+str` явно преобразуют строку в число. Преобразование не проверяет требования задачи: результат может быть `NaN`, дробным, выходить за границы или быть нулём из пустой строки.

`NaN` — значение числового типа. `NaN === NaN` возвращает `false`; для проверки используется `Number.isNaN(value)`.

`Number.isInteger(value)` возвращает Boolean, а не преобразованное число. Для `0` результат `true`, для `2.5` и `NaN` — `false`.

## Проверка пользовательского ввода

Отдельные шаги: проверить пустоту при необходимости, преобразовать, проверить целочисленность и диапазон. Граница «включительно» требует `>=` или `<=`.

Решение температуры после подсказки о целочисленности:

```js
function isValidTemperature(str) {
  const strTrim = str.trim();
  if (!strTrim.length) return false;
  const strTrimNumb = +strTrim;
  return Number.isInteger(strTrimNumb)
    && strTrimNumb >= -10 && strTrimNumb <= 40;
}
```

Ноль допустим, поэтому пустую строку необходимо отличить от строки '0'. Для количества от 1 до 99 пустота после преобразования отсекается нижней границей.

Ранний возврат (early return) завершает функцию сразу, когда результат уже известен. `условие ? true : false` можно заменить самим булевым условием.

## Логические операторы

`||` возвращает левый операнд, если он truthy, иначе правый. `&&` возвращает левый, если он falsy, иначе правый. `??` выбирает правый только для `null` или `undefined`. Операторы возвращают значения операндов, не обязательно Boolean. Правая часть вычисляется только при необходимости (short-circuit evaluation).

```js
0 || 10;         // 10
0 ?? 10;         // 0
'' || 'нет';     // 'нет'
'' ?? 'нет';     // ''
undefined ?? 10; // 10
0 && 'готово';   // 0
2 && 'готово';   // 'готово'
```

Для громкости 0 — допустимое значение; значение по умолчанию удобно выбирать через `??`.

В React выражение `items.length && <span>Товары</span>` при пустом массиве возвращает 0, который отображается. Исправления: `items.length > 0 && <span>Товары</span>` либо тернарное выражение с `null`/`false` для пустого массива.

## Итог и точки повторения

Первичная диагностика типов и const: верно. Первоначально путались границы блока/функции, TDZ и глобальная область var. Повторная проверка примеров выполнена верно после объяснений.

Валидация количества и температуры выполнена с подсказками: исправлены хранение Boolean вместо числа, пропуск целочисленности и исключение верхней границы. Итоговая parseQuantity написана самостоятельно после этих упражнений; исходный код сохранён в exercises/parse-quantity.js.

Выводы пользователя: let/const ограничены блоком, var — функцией; пустая строка превращается в 0; преобразование может дать NaN. Уточнения преподавателя: TDZ вызывает ошибку только при обращении; даже успешно преобразованное число требует проверки по условиям задачи. Эти две формулировки стоит повторить на следующем занятии.
