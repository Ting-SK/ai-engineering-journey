# Подсчёт частот и сложность алгоритма

## Map и частоты

Частота — количество появлений значения. Map хранит пары «ключ → значение»: здесь статус → количество. Методы: set(key, value), get(key), has(key). Для отсутствующего ключа get возвращает undefined. Изменение содержимого Map допустимо при объявлении переменной через const.

Для ['ok', 'error', 'ok'] состояния: ok → 1; затем ok → 1, error → 1; затем ok → 2, error → 1.

Пользователь самостоятельно написал обновление:

```js
counts.set(status, counts.has(status) ? counts.get(status) + 1 : 1);
```

Эквивалентный вариант для числовых счётчиков:

```js
counts.set(status, (counts.get(status) ?? 0) + 1);
```

## Первый уникальный и первый повторный

Первый уникальный статус встречается ровно один раз во всём массиве. Сначала считаем все частоты, затем идём по исходному массиву и сразу возвращаем статус с частотой 1. Если продолжать записывать результат без выхода, получится последний уникальный. При отсутствии ответа возвращаем null.

Идея добавлять значение в Set при первом появлении и удалять при следующем не решает задачу уникальности: третье появление снова добавит значение. Это отслеживает нечётность количества появлений. Контрпример: ['ok', 'ok', 'ok', 'error'].

Первый повторный — статус, чьё повторное появление первым встретилось при обходе слева направо. В Set храним уже увиденные значения; если has(status) возвращает true, сразу возвращаем status, иначе добавляем его. Можно ответить за один проход: дальнейшие элементы уже не изменят найденный факт повтора. Для уникальности же нужно убедиться, что значение не повторится дальше.

Для ['ok', 'error', 'error', 'ok'] первый повторный — 'error'. Для пустого массива обе функции поиска возвращают null.

## Время и память

n — число элементов, k — число уникальных значений. В обычной модели хеш-таблицы операции Map/Set в среднем считаем O(1); это допущение анализа, а не гарантия постоянного времени каждой операции.

Подсчёт частот: ожидаемое время O(n), дополнительная память O(k). Два последовательных прохода первого уникального: n + n = 2n, ожидаемое время O(n), память O(k). Первый повторный: максимум n просмотренных элементов, ожидаемое время O(n), память максимум O(k); ранний возврат может сократить работу.

Вложенный filter просматривает весь массив для каждого элемента. Для n одинаковых статусов условие count === 1 никогда не выполняется: n × n = n² сравнений. Для 1000 элементов это 1 000 000, для 3 — 9. Такой вариант имеет квадратичное время в худшем случае.

| Увеличение входа | Линейная модель n | Квадратичная модель n² |
|---|---|---|
| В 2 раза | Работа растёт в 2 раза | В 4 раза |
| В 3 раза | В 3 раза | В 9 раз |

Для модели n² переход от 100 к 200 элементам: 10 000 → 40 000 сравнений. Коэффициент роста: 40 000 / 10 000 = 4. Big O описывает порядок роста, а не точное число операций или секунд.

3000 элементов с тремя разными статусами требуют трёх записей в Map. В худшем случае k = n. Память исходного массива не включаем в дополнительную память.
