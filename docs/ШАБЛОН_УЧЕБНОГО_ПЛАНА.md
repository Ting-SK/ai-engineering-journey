# Шаблон учебного плана: AI / LLM Application Engineer

## Как использовать шаблон

Это пример годового маршрута для разработчика с опытом JavaScript/React, который начинает изучать ИИ. Если опыта программирования пока нет, добавьте подготовительный этап по основам языка, Git и HTTP и пересмотрите сроки.

1. Создайте собственную копию репозитория или отдельный учебный репозиторий.
2. Скопируйте этот файл в свой `docs/УЧЕБНЫЙ_ПЛАН.md`. Если файл с таким именем уже есть, сначала сохраните его или выберите другое имя: копирование не должно стереть нужный прогресс.
3. Заполните поля `[заполнить]`: опыт, ограничения, расписание, часовой пояс и дату старта.
4. Адаптируйте нагрузку и параллельный фронтенд-маршрут под свои знания. Приведённое расписание — пример.
5. Составьте первую неделю с реальными датами и начните с диагностики знаний.
6. Ведите фактический прогресс только в своей рабочей копии. Этот `ШАБЛОН_УЧЕБНОГО_ПЛАНА.md` оставьте чистым шаблоном.

Папки `S1/`–`S4/`, темы, упражнения, домашние работы и проекты добавляйте по мере обучения. В каждом проекте храните собственный README с инструкцией запуска. После занятия обновляйте журнал, проверяйте изменения и сохраняйте результат коммитом в своём репозитории.

## 3. Постоянное расписание

Пара — 90 минут, перерыв между парами — 15 минут. Ниже приведён пример расписания; выберите удобные дни и часы. Часовой пояс — [заполнить].

| День | Время | Занятие |
|---|---|---|
| Вторник | 19:00–20:30 | Основной предмет: теория текущего этапа |
| Вторник | 20:45–22:15 | Практика по изученной теме |
| Четверг | 19:00–20:30 | Основной предмет: продолжение и упражнения |
| Четверг | 20:45–22:15 | Лабораторная / работа над проектом |
| Суббота | 10:00–11:30 | Фронтенд: теория, терминология, архитектура |
| Суббота | 11:45–13:15 | Задачи на JavaScript, практические кейсы и алгоритмы |

При таком расписании понедельник, среда, пятница и воскресенье — без обязательной учёбы. Не переносить пропущенные занятия на дни отдыха автоматически.

Пример структуры пары: 10 минут повторения, 30 минут нового материала, 40 минут самостоятельной практики, 10 минут фиксации результата. На лабораторной основное время отдаётся коду.

Первые две недели — проба нагрузки. При перегрузке на работе допустим сокращённый режим: две пары основного предмета за неделю. Не создавать накопительный долг по часам.

## 4. Учебный календарь

- Четыре семестра по 12 учебных недель: всего 48 недель.
- Четыре недели на каникулы и резерв: по одной после семестра либо с переносом по необходимости.
- Каждая четвёртая учебная неделя преимущественно посвящается закреплению и закрытию пробелов.
- Недели 11–12 каждого семестра — итоговая работа и проверка знаний.
- Конкретные календарные даты заполняются после выбора даты старта.
- Сроки корректируются по результатам; не переходить дальше только потому, что закончилась календарная неделя.

## 10. Портфолио и критерий готовности

Два основных приложения:

1. Извлечение данных из документов: Python API, валидация, набор проверок, сравнение решений.
2. Помощник по документации: React + Python, RAG, источники, инструменты, контроль действий и мониторинг.

Дополнительные результаты: небольшой эксперимент с классическим ML, сравнение моделей, при возможности эксперимент с локальной моделью или дообучением.

У каждого основного проекта должны быть:

- задача и целевой пользователь;
- инструкция запуска;
- схема архитектуры и объяснение решений;
- тесты и оценка качества на примерах;
- измерения задержки и расходов;
- ограничения и разбор ошибок;
- демонстрация работы.

Критерий готовности: самостоятельно взять задачу, выбрать подход, собрать сервис, измерить качество, развернуть и объяснить ограничения. Вакансии просматривать примерно со второго семестра, первые пробные интервью — с четвёртого.

## 11. Правила продолжения в новом чате

Для ассистента, ведущего обучение:

1. Прочитать файл полностью, особенно текущую точку, журнал, решения и передачу контекста.
2. Сохранить цель, расписание и последовательность семестров. Не возвращаться к выбору профессии и языка без запроса пользователя.
3. При старте семестра составить ближайшую неделю с конкретными темами, источниками и практикой. Не выдавать весь год повторно.
4. Объяснять новые термины по-русски; английское название приводить рядом. Проверять понимание на примерах.
5. Опирайтесь на опыт, указанный в разделе 1; проверяйте исходные знания и не предполагайте знание Python и ML.
6. Давать самостоятельную попытку до готового решения. Использование ИИ разрешено, но проверять способность объяснить и воспроизвести результат.
7. Обновлять прогресс только по фактически выполненной работе. Различать «прочитал», «решил с помощью» и «выполнил самостоятельно».
8. После занятия обновить текущую точку и добавить запись в журнал. Перед редактированием перечитать актуальный файл, чтобы сохранить изменения других чатов.
9. При завершении семестра заполнить передачу контекста и результат зачёта. Переход согласовать по фактической готовности.
10. При недоступности файла сообщить об этом; не утверждать, что контекст прочитан или прогресс сохранён.
