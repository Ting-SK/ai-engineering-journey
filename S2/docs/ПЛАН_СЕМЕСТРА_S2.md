## Программа и итоговая работа

**Статус:** не начат.

**Цель:** понимать основы работы моделей и создавать ИИ-функциональность через API с измеримым качеством.

| Недели | Основное содержание |
|---|---|
| 1–4 | Классификация и регрессия, baseline, обучающая/проверочная/тестовая выборки, переобучение, утечка данных, precision/recall/F1. NumPy, pandas, scikit-learn. Векторы, матрицы, вероятность, статистика, смысл производной и градиента |
| 5–8 | API моделей, инструкции и примеры, структурированные ответы и проверка схем, streaming, отмена, тайм-ауты, повторы, ограничения частоты, стоимость и задержки |
| 9–10 | Наборы проверочных примеров, сравнение моделей и промптов, разбор ошибок |
| 11–12 | Завершение проекта и разбор результатов |

**Субботние темы:** TypeScript — narrowing, generics, unions, unknown, типизация API. React — рендеры, состояние, эффекты, зависимости, keys, stale closures. Алгоритмы — два указателя, sliding window, стек, очередь и бинарный поиск.

**Итоговая работа:** извлечение структурированных данных из документов с валидацией результата и набором проверочных примеров.

**Зачёт:** сравнить два варианта решения на одинаковых примерах, объяснить качество, скорость, стоимость и типичные ошибки. Не подбирать все настройки по финальной тестовой выборке.

**Источники:**

- [Учебник ML от ШАД](https://education.yandex.ru/handbook/ml) — выбранные разделы; это продвинутый материал, не обязательное чтение целиком.
- [Hugging Face LLM Course на русском](https://huggingface.co/learn/llm-course/ru/chapter1/1) — выборочно, после подготовки по Python и ML.
- Документация выбранного поставщика API моделей — определить при начале этапа с учётом доступности и бюджета.

## Правила обновления

1. Перед занятием прочитать общий план и этот файл; перед редактированием перечитать актуальные версии обоих.
2. Общий план — основной источник текущего состояния. В этот файл копировать относящиеся к S2 записи занятий, прогресс, домашние работы и решения.
3. После занятия обновлять оба файла в одном наборе изменений. Использовать одинаковый ID занятия; при исправлении обновлять существующую запись в обоих журналах, не создавать дубликат.
4. Ссылки на материалы корректировать относительно расположения файла: из общего плана — `../S2/…`, из этого файла — `../…`.
5. При расхождениях сверить фактическую работу и историю изменений. Не отмечать тему освоенной только по календарю или наличию материалов.
6. При завершении семестра скопировать итог и передачу контекста в общий план. Файл `docs/ШАБЛОН_УЧЕБНОГО_ПЛАНА.md` в корне репозитория не заполнять личным прогрессом.
