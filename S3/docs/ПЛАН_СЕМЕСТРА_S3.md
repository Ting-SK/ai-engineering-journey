## Программа и итоговая работа

**Статус:** не начат.

**Цель:** создавать приложения, которые используют собственные документы и внешние инструменты.

| Недели | Основное содержание |
|---|---|
| 1–5 | Embeddings, очистка и разбиение документов, метаданные, векторный и полнотекстовый поиск, гибридный поиск, ранжирование, сбор контекста и RAG |
| 6–7 | Раздельная оценка поиска и ответов, ссылки на источники, отсутствие ответа, обновление документов и права доступа |
| 8–10 | Tool calling, схемы и проверка аргументов, состояние процесса, workflow и агент, лимиты шагов/времени/расходов, идемпотентность, восстановление, подтверждения, основы MCP |
| 11–12 | Интеграция и проверка проекта |

Сначала собрать небольшой процесс обычным Python-кодом; затем оценить пользу одного фреймворка оркестрации. Не добавлять автономность без потребности задачи.

**Субботние темы:** границы модулей, зависимости и публичные интерфейсы, разделение UI/бизнес-логики/данных, локальное/глобальное/серверное/URL-состояние, API-слой, тестируемость, дизайн-система, ADR. Алгоритмы — рекурсия, деревья, графы, BFS/DFS.

**Итоговая работа:** помощник по документации с источниками и несколькими контролируемыми действиями.

**Зачёт:** показать поведение при неправильном поиске, нехватке данных, ошибке инструмента и превышении лимита; восстановить последовательность действий по журналу.

**Источники:**

- [LlamaIndex — введение в RAG, английский](https://developers.llamaindex.ai/python/framework/understanding/rag/).
- [Hugging Face — Agents Course, английский](https://huggingface.co/learn/agents-course/en/unit0/introduction).
- [Русский перевод Agents Course в репозитории](https://github.com/huggingface/agents-course/blob/main/units/ru-RU/unit0/introduction.mdx).
- [Anthropic — Building effective agents, английский](https://www.anthropic.com/research/building-effective-agents).

## Правила обновления

1. Перед занятием прочитать общий план и этот файл; перед редактированием перечитать актуальные версии обоих.
2. Общий план — основной источник текущего состояния. В этот файл копировать относящиеся к S3 записи занятий, прогресс, домашние работы и решения.
3. После занятия обновлять оба файла в одном наборе изменений. Использовать одинаковый ID занятия; при исправлении обновлять существующую запись в обоих журналах, не создавать дубликат.
4. Ссылки на материалы корректировать относительно расположения файла: из общего плана — `../S3/…`, из этого файла — `../…`.
5. При расхождениях сверить фактическую работу и историю изменений. Не отмечать тему освоенной только по календарю или наличию материалов.
6. При завершении семестра скопировать итог и передачу контекста в общий план. Файл `docs/ШАБЛОН_УЧЕБНОГО_ПЛАНА.md` в корне репозитория не заполнять личным прогрессом.
